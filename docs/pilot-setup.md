# Dedicated SmarterTeens owner pilot
No existing AuroTap, Neerva or legacy MongoDB data may be reused or deleted. Provision a new Supabase project only after organization and cost are approved. Prefer Mumbai if available. Apply db/bootstrap.sql once to that project after reviewing it; do not run on any other project. Set SUPABASE_URL and SUPABASE_PUBLISHABLE_KEY in the SmarterTeens Vercel preview environment (never a service role key). Disable public signup and anonymous sign-in, require verified email, manually invite a verified pilot owner, and configure auth rate limits. The access-token-only cookie expires in at most one hour; users must sign in again. No persistent refresh token is stored. Do not enter real minors' personal data or take payments in the pilot.
## Verify before release
Create two separate verified synthetic owner accounts A and B. Create institute A/B and batches/learner codes. Check anonymous reads/writes are denied, A cannot read/insert B rows through REST even with B IDs, cross-institute FK fails, duplicate attendance and receipts fail, and receipt amount cannot differ from invoice. Verify same-origin check in Vercel, logout, expired session, sign-in throttling, and correct database env. Test 360px/mobile browser. No update/delete, partial payment, correction, staff login, public registration, real data, guardian links, payment processing or complete reporting is available in this slice. Add these with explicit authorization and audit requirements before wider launch.
