# Platform operations rollout
Apply platform-governance.sql after previous migrations and before deploying the new session/API code. Provision authorized platform operators out of band into st_private.platform_admins; no automatic elevation or public signup. Operators can list nonanonymous registered accounts with email/UUID search, suspend or restore app access (not delete), and review immutable action history. Restrictive RLS policies cover all current private application tables and the API checks current account state every request. Existing JWTs cannot bypass those RLS controls, but Auth-provider access itself is not banned or revoked; a restored account may use a still-valid session. Protect future tables with the same policy and add coverage. No raw auth credentials, password resets, user deletion, role assignment or unrestricted impersonation are available. Keep platform operators separate from commercial and marketplace roles; require MFA and operational approval before live admin access.
Analytics are current DB totals and 30-day counts, not forecasts, active engagement or accounting revenue. Verified platform payment value reflects manual bank verification; institute receipts are separate. Readiness performs an actual Data API/DB round-trip and returns 503 on failure; liveness endpoint remains cheap. Admin health display is on demand, not continuous monitoring, automatic alerting or recovery. Configure a monitored canonical production URL and alerting after deployment, with approved cadence and cost controls. No production test records or paid tools.
