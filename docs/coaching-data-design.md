# Coaching domain requirements (not implemented)
Use PostgreSQL with tenant_id on institute-owned entities, composite tenant/ID foreign keys and default-deny row authorization. Derive tenant from a verified membership, never from client input. Platform admin access is separate and audited. Use a managed auth provider with server-verified sessions and no public service keys.
Entities: institute, membership, guardian link, consent, student enrollment, batch, attendance, fee invoice, payment, allocation, receipt, subscription, entitlement, audit event, project submission, rubric review. Use integer paise for INR, immutable financial events, idempotency keys and unique provider event IDs. Require server-side recalculation and verified payment webhooks. No sensitive student data in logs or analytics. Define retention and deletion policy before storing minors' data.
Acceptance: cross-tenant read/write denial, guardian sees only linked learner, teacher assigned batch only, duplicate payment webhook has no extra effect, transaction rollback on failed allocation, export and restore rehearsed. Revenue targets are hypotheses; measure activation, monthly renewals, gross margin, acquisition cost and paid conversion. No live charges until approved.
